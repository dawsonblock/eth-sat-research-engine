# Count recovery and the conditional recursion bound

This note separates deductions from their required hypotheses. Its source is
the [pinned Appendix D](https://github.com/openai/math/blob/4eaee87548250b2682affda7d05d947c05554bae/preprints/The-Exponential-Time-Hypothesis-is-False-October-25-2026/build/quantitative-contraction.tex),
whose complete argument has not been independently verified here. The
finite implementation is not a theorem-scale realization of that argument.

## Root precision for an unweighted Boolean count

For a count-preserving reduction of a CNF with exactly `n` declared
variables, including unused variables, the integer count `C` satisfies
`0 <= C <= 2^n`. If an exact completed contraction gives `C mod 2^p` and
`p >= n+1`, then `C < 2^p`, so the canonical residue equals `C`.
In contrast, at `p=n`, both zero and the largest possible count have residue
zero. For `n=0`, one bit suffices. This conclusion does not apply unchanged
to arbitrary signed or weighted tensor contractions.

`recover_boolean_count` enforces the strict precision and integer range
conditions without constructing a potentially enormous modulus. It assumes
the caller has already established both the correctness of the residue and
the count-preserving relationship to the declared CNF. A failed or incomplete
contraction must not be passed off as a verified residue.

## Conditional recursion calculation

Let `lambda=ceil(log2(s))`, and suppose every active node on every path
has at most `M_d <= C s rho^d` edges, with `rho=3/32`, and
`u_d >= c lambda/2^d` for fixed positive constants `C,c`. The latter is
required only at active depths; the actual schedule uses integer floors and
must switch to a justified leaf before its lower bound fails. Suppose also
that all packet, valuation, precision, and mode-count hypotheses apply and
that the number of recursive calls generated by an active node, including
interpolation and the 64 children per retained tuple, is at most
`poly(s) exp(K M_d/sqrt(u_d))` for a fixed constant `K`. Then the cumulative
exponent along an active path is bounded by

\[
K\sum_d \frac{M_d}{\sqrt{u_d}}
\le \frac{KC}{\sqrt c}\frac{s}{\sqrt\lambda}
      \sum_d (\rho\sqrt2)^d
= O\!\left(\frac{s}{\sqrt{\log s}}\right),
\]

because `rho sqrt(2) < 1`. The prescribed leaf cutoff
`H=ceil(s/floor(sqrt(lambda)))` and shrinkage imply `O(log lambda)` active
levels for fixed `C`. Multiplying a fixed `poly(s)` factor per level costs
`exp(O(log(s) log(lambda)))`, which is absorbed by the displayed exponent
for sufficiently large `s`. A direct leaf costs at most `2^H` assignments,
before its tensor-entry and bit costs are charged.

Consequently, a full bit-operation bound also needs uniform bounds on
packet construction, the number and cost of interpolation points, tensor
entry evaluation, arithmetic precision, and the cost of each leaf. The
dependence on input-description length must remain a fixed polynomial;
repeating an unrestricted `poly(description length)` factor at each
recursive depth does not by itself establish that. The number of tuples is
not the number of arithmetic operations, and a leaf fallback at an arbitrary
large active node does not preserve the claimed asymptotic bound.

Polynomial space is a separate obligation: immutable entry recipes,
precision lifts, tuple enumeration, interpolation accumulators, and the
depth-first call stack must all have polynomial bit size. The finite
implementation's work ledger omits some of these costs. Its instance checks
and the conditional estimates above do not prove that all of the required
hypotheses hold uniformly in the code.
