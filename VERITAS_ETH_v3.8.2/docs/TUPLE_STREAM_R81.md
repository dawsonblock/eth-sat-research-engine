# R8.1: finite structural tuple stream checks

The previous finite recursor checked only the number of emitted tuples against
a count generated by the same DFS implementation. A fault that replaced one
valid tuple with a duplicate preserved the count and produced an accepted
residue 4 instead of 3. An individual tuple oracle did not catch the change,
because both occurrences were individually correct.

## Verification contract

The source mode certificate is checked as before. The separate
`tuple_stream_check` derives immutable constraints from those checked modes:
positive weights, each mode's number of available target rows, and the union
of target rows for each `(packet, target_group)`. It counts the permitted
exponent vectors without using the DFS stream. For each group, a sparse DP
tracks `(sum of exponents, weighted sum)`, applies each mode's individual
bound, and truncates at the group row capacity and the working precision. A
second sparse convolution combines the resulting group polynomials and sums
coefficients of degrees below the precision. Counts and live DP states are
explicitly capped; overflow returns an inconclusive result.
The reference functions also expose the direct interfaces
`independent_weighted_tuple_count(modes, precision)` and
`independently_valid_tuple(beta, modes, precision)`.

Each emitted tuple is independently checked for exact integer type, length,
nonnegative exponents, individual row capacity, combined group row capacity,
and weighted sum below precision. Tuples must be strictly lexicographically
increasing. The independently computed cardinality must agree with both the
mode certificate and the number emitted. Membership plus strict ordering
establishes distinctness; equal cardinality with the independently counted
finite constraint set establishes that this specific set is exhausted. Only
the previous tuple is retained for ordering. The recursor and the standalone
point-child expansion enforce the same conditions. Failure and budget
exhaustion produce no partial count or certificate.

This is a finite completeness check for the **structural constraint domain**.
It does not independently establish that the checked mode certificate covers
all source modes, prove that structural pruning is sound for every possible
network, or establish the manuscript's asymptotic runtime or space bounds.
Integer bit costs, source validation, and allocations remain incompletely
metered. The DP's item visits are charged to the cooperative work ledger.

## Small direct point checks and certificate compatibility

The finite recursor now checks the point-child sum against the direct half-edge
oracle by default for active calls of at most two wires. Explicit
`verify_point_identities=True` requests the oracle for all active calls within
`point_oracle_edge_limit`. The mandatory automatic threshold can be raised but
not lowered below two wires, and is recorded in V2 certificates. The result
reports point-identity coverage. These direct
checks remain bounded and share the ring and Cauchy implementations. They are
not a theorem proof or a substitute for independent review.

New transcripts use `VERITAS_FINITE_TAPERED_V4_TRANSCRIPT_V2`. Legacy V1
transcripts are replayed with their original point-check policy while the new
structural stream checker runs afresh. Successful replay remains same-code
finite evidence, not independent verification.

## Reproduction

```sh
PYTHONPATH=src python -m pytest -o addopts= -q \
  tests/test_r81_tuple_stream.py tests/test_structural_tuple_streaming.py \
  tests/test_tapered_tuple_work.py tests/test_v39_point_child_certificate.py
```

The tests compare the independent count with a separate brute-force Cartesian
oracle on seeded overlapping groups. They inject same-count substitution,
duplicates, reversed order, invalid vectors, omission, shared generator/precount
corruption, checker budget exhaustion and direct point-oracle disagreement.
The theorem branch remains disabled.
